# Security remediation — 19 October 2026

This change addresses the OTP lead and C1–C17 from `security-audit-skill/piltoverarchive/run-3`. Those reports were leads, not independently verified findings. Regressions here exercise the affected behavior with local PostgreSQL, HTTP, JMAP, S3 and PA fixtures. No production service, credential, account or upstream deck was changed during this work.

## Deployment order and compatibility

1. Ship the web/client auth changes with the backend so verification pages use explicit confirmation and a separate password sign-in. Native collection/deck writes now send `X-Astral-Request: 1`; existing native clients remain compatible through their `application/json` requests. This fallback applies only without Origin, Referer or browser fetch metadata; simple form content types are rejected, and cross-origin JSON remains subject to the exact CORS allowlist. Exercise a real Android and iOS install before rollout. Browser flows and legacy native HTTP requests are covered locally; installed-device behavior is not.
2. Restrict the GitHub `internal-releases` environment to protected `main`, with the desired required reviewers. Move release/Expo/Discord secrets into that environment and remove repository-level copies. A workflow YAML condition alone cannot protect repository secrets from a writer who changes the workflow. Check fork-secret settings and prior runs; rotate credentials if exposure is established. This change does not establish that a secret was stolen.
3. Create a separate private release bucket. Give CI a credential for that bucket only and the backend a separate read-only credential. Configure `RELEASE_S3_ENDPOINT`, `RELEASE_S3_REGION`, `RELEASE_S3_BUCKET`, `RELEASE_S3_ACCESS_KEY_ID`, `RELEASE_S3_SECRET_ACCESS_KEY` and an independent random `RELEASE_LINK_SECRET`. CI maps its release credential to the existing publisher `S3_*` inputs. Confirm its credential cannot access the image bucket.
4. The backend no longer signs or verifies release links with `S3_SECRET_ACCESS_KEY`; set `RELEASE_LINK_SECRET` before deploying. Preserve permanent release URLs during that migration: copy and verify existing `releases/` objects into the new bucket before switching reads. Set `RELEASE_LINK_LEGACY_SECRET` to the previous signing value only if retaining previously distributed links is intended. The backend temporarily supports legacy image storage/key configuration when dedicated settings are absent; credential isolation is complete only after dedicated settings are installed. Test old/new HTML, QR, APK and IPA/plist links. Real-device installation remains a deployment check.
5. **Rollout blocker:** record the actual Railway/proxy chain in staging before setting `TRUSTED_PROXY_CIDRS`. Production refuses to start without it, because otherwise every client behind the proxy shares one identity and a few failed sign-ins from anyone throttle everyone. Only trust controlled proxy addresses whose forwarding behavior has been verified; never use `0.0.0.0/0` or `::/0`. Check two real clients and forged `X-Real-IP`/`X-Forwarded-For` headers through every public ingress. No live Railway header behavior was assumed or verified here.
6. Set exact trusted application origins. Keep cookies host-only unless a reviewed integration requires a domain cookie. Inventory old parent-domain cookies and plan scoped expiration/session invalidation if needed; changing the default does not erase existing browser cookies. Confirm sign-in, sign-out and renewal through the deployed web/API origins, including legacy-cookie coexistence.
7. Back up the database and verify recovery before applying the normal forward migrations. Migrations `0016_private_upstream_decks.sql` and `0017_private_legacy_deck_ids.sql` add the quarantine table and legacy entries without deleting or rewriting user decks. Verify the migration ledger, startup idempotence and owned/community deck flows. The new table can remain during rollback.
8. Update locally managed development tunnels to credential-file configuration or the API-only quick-tunnel path. Existing remotely managed token tunnels must be reconfigured before this launcher will start them. Verify API reachability and that `/`, Metro bundle paths and debugger paths return 404.
9. Review PA key scope and historical upstream visibility. Prefer a credential/identity restricted to the intended catalog and public community reads where PA supports that distinction. Known mirrors are quarantined locally, but orphaned historical copies require an owner-side inventory and visibility repair before claiming complete closure of C5. Set `UPSTREAM_SERVICE_AUTHOR` to the PA author name shown on a known mirror so decks written under the shared key stay hidden even when no local row records them.

The intentional behavior changes are: unused OTP login/recovery is disabled; email verification and password reset no longer sign the recipient in; private owned decks are no longer silently published through a shared PA identity; untrusted browser writes and unsupported tunnel modes are rejected. Supported password login, manual verification, recovery, owned deck CRUD, community import and collection workflows retain explicit tests.

For rollback, retain the pre-deployment image digest, configuration snapshot and database backup with tested recovery. Prefer reverting the faulty change while keeping the OTP shutdown, origin checks and shared-key write prohibition. A full old-image rollback reopens those paths and must retain equivalent ingress containment. Keep the additive quarantine table and release objects; retain the explicit legacy signing key only for the agreed link-migration window. Do not use a destructive database reset to roll back this change.

## Historical data follow-up

Code changes prevent new unsafe writes but cannot undo past exposure. Run a read-only inventory against a snapshot before scheduling any repair:

```sql
-- Known historical mirrors, including the ambiguous legacy mappings.
SELECT id, payload->>'upstreamId' AS upstream_id,
       payload->>'importedFromId' AS imported_from_id
FROM user_decks
WHERE payload->>'upstreamId' IS NOT NULL
  AND (payload->>'importedFromId') IS DISTINCT FROM (payload->>'upstreamId');

-- Existing stacks that may have bypassed CSV field validation.
SELECT id, collection_id, language
FROM collection_items
WHERE char_length(language) > 16;
```

Compare all imported/owned upstream mappings with PA ownership and visibility using owner-authorized evidence. Previously deleted local decks may have orphaned upstream copies that this database cannot identify. Quarantine prevents access through this API for known IDs; it does not unpublish content on PA. Do not delete or overwrite upstream decks under the shared key. Repair legacy collection fields with a reviewed mapping that preserves quantities, handles stack-key collisions and keeps a rollback record; do not silently truncate or merge records. Also inventory historical over-limit profile/notes/grading fields before deciding whether data repair is needed.

## Reproducing checks

Use the checked-in toolchain and local PostgreSQL 16 on port 5433. Tests reject non-loopback/non-test database targets and use synthetic accounts and local network fixtures. Do not substitute production URLs or credentials.

```bash
bun install --frozen-lockfile
bun run check
bun run test

# Production image, plus HTTP and browser suites using its extracted executable.
podman build -f Dockerfile.backend -t astral-grove-backend:security-local .
# Extract /usr/local/bin/astral-grove-server from that image into /tmp/astral-security-release.
TEST_DB_URL=postgres://riftbound:riftbound@localhost:5433/riftbound_test \
  ASTRAL_BACKEND_BIN=/tmp/astral-security-release bun run --cwd apps/backend test:http
TEST_DB_URL=postgres://riftbound:riftbound@localhost:5433/riftbound_test \
  ASTRAL_BACKEND_BIN=/tmp/astral-security-release bun run --cwd apps/backend test:perf
TEST_DB_URL=postgres://riftbound:riftbound@localhost:5433/riftbound_test_security_ui \
  ASTRAL_BACKEND_BIN=/tmp/astral-security-release bun run test:security-ui
```

Provision the separate browser test database with `CREATE DATABASE riftbound_test_security_ui` if absent. Use separate test databases for concurrently running HTTP and browser suites. `test:security-ui` seeds the committed catalog fixture and runs security, auth, catalog ownership/prices, collection, deck and sharing browser flows. `UI_E2E_SPECS` can select other comma-separated Playwright specs. CI retains development HTTP, production HTTP and production performance jobs, and adds a production-binary browser job.

The native JSON compatibility fallback follows [OWASP's guidance on rejecting simple requests](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html#disallowing-simple-requests). Tests retain rejection of sibling/null origins and browser fetch metadata even when `application/json` is supplied.

## Dependency advisory follow-up

The available compatible fixes were pinned for `brace-expansion`, `shell-quote`, `smol-toml` and `source-map-js`. This does not make the entire dependency audit clean. At the time of this work, the advisory service still reported:

- [braces](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm), [http-cache-semantics](https://github.com/advisories/GHSA-ch52-4w7c-c8xp), [node-forge](https://github.com/advisories/GHSA-86w9-cpqp-85rv) and [sprintf-js](https://github.com/advisories/GHSA-hp3w-g68c-fv3c): no published patched version listed in the advisory metadata.
- [image-size](https://github.com/advisories/GHSA-5p2g-fcmc-qvqq) and its [ICNS parser advisory](https://github.com/advisories/GHSA-w3rx-r6r6-pgpr): fixed in 2.0.3, while Metro tooling uses 1.x. A major-version override needs a separate compatibility check or maintained backport.

These are unresolved dependency leads, not verified reachable production exploits. The production API image contains the Rust executable without Node/Bun, but that does not establish safety of development/build tooling or mobile bundles. Do not suppress the advisories or claim full dependency audit completion. Rust advisory matching and the original audit's unassigned coverage gaps remain separate audit work.
