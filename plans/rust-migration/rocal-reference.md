# Rocal Rust migration: source map and adaptation

Inspected on 2026-10-18 at `b28edbe04e1ecccbe01ebf4e77b173f6d4a12a8e`, branch `master`, in `~/Documents/rocal`. Rocal's pre-existing untracked `experiments/` and `scripts/repair-history-pr.py` were left alone. No Rocal application code was changed. Historical deployment, benchmark and suite results below are reported by its checked-in plan; they were not independently rerun against its production service in this task.

The main source is `plans/001-rust-backend-migration.md`. Read its result sections together with the original proposal: the final auth implementation, directory layout, deployment and worker scope differ from the starting plan.

## Type contract details worth preserving

Rocal's Rust DTO crate depends on Serde, Serde-with and utoipa, not the database entity crate. DTOs serialize camelCase. `packages/api-contracts` exports generated wire types, and clients import those through `Schema<Name>`. Client-only models that revive dates or carry view state stay separate.

`xtask/src/openapi.rs` gets the document directly from `solace_server::openapi()`, checks unique operation IDs, writes JSON, runs the TypeScript generator with `--no-env-file`, and checks the resulting Git diff. It does **write** generated source even with `--check`; during Astral Grove implementation prefer comparing generation in a temporary directory so a checker does not overwrite unrelated work.

The route `OpenApiRouter` plus `routes!` registration ties endpoints and metadata together. That does not prove the runtime validator's behavior. Rocal added `http/contract_tests.rs` after review found required/null/integer mismatches, and later added current-source differential probes for JavaScript date/timezone semantics. Put both gates in Astral Grove's first skeleton.

Rocal uses strict request objects. Astral Grove's current Zod schemas normally strip unknown keys, so its Rust validators/Serde strategy must reflect that difference. Copying `deny_unknown_fields` across this API would be a breaking change despite a successful build.

## Database and auth decisions that do not transfer verbatim

- Rocal retained 53 Prisma migrations and UTC `timestamp(3)` columns. Astral Grove has 16 committed Drizzle migrations, `timestamptz(6)`, decimal price columns, generated search columns and PostgreSQL extensions. Its Rust migration runner needs Drizzle history compatibility, not Prisma's ledger.
- Rocal's IDs included Prisma CUID defaults. Astral Grove has upstream UUIDs, database-generated collection UUIDs, text auth IDs, text deck/version IDs and deterministic SHA-derived price UUIDs. Map each source of identity explicitly.
- Rocal has 14-day sessions and a Solace-specific cookie-domain policy. The constructed Astral Grove auth context reports seven days, one-day renewal/freshness, no cookie cache, and a 12-unit password minimum. Preserve Astral Grove's `auth-advanced.ts`, cookie-domain and trusted-origin behavior.
- One reason the generic auth library failed Rocal was its timezone-bearing entity timestamps. Astral Grove's timezone-bearing columns remove that specific mismatch; they do not prove the library's schema, cookies, OTP or Expo behavior compatible. The primitives design already provides the necessary protocol control.
- Solace's invite-gated signup, passkeys, encrypted account state, worker, push and calendar/mail-account provisioning are outside this product's rewrite. Astral Grove's collection invites are a separate domain, not an auth-signup gate.

## Later Rocal fixes and the gate they motivate

These are historical defects/fixes recorded in Rocal's plan and current source; do not report the old findings as still open at the inspected head.

| Historical problem                                                              | What the migration must test here                                                                               |
| ------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Green suites missed malformed Unicode parser panics and scheduler failure       | Malformed/non-ASCII input, captured panic behavior, and continued operation of later syncs/imports              |
| Date fractions and a legacy timezone alias differed from JS                     | Compare parser output, truncation and round trips with current TS; preserve precise activity cursors separately |
| Raw verifier errors echoed request contents into logs                           | Capture logs with sentinels for credentials, tokens, email and upstream payloads; log categories only           |
| Destination verifier followed the old crate path after moving code              | Verify actual case identifiers under the final file layout; fail stale/pending destinations                     |
| `list-accounts` was absent although the typed auth client called it dynamically | Inspect installed auth endpoint tables as well as static frontend calls; add route completeness checks          |
| OpenAPI nullability and integer widths disagreed with validators                | Probe schema→validator→Serde behavior with missing/null/boundary/overflow values                                |
| Existing bulk-operation authorization holes survived the initial behavior port  | Require safety invariants beyond exact old behavior; track intentional fixes with named differences             |
| Pool acquire checks introduced an extra SQL round trip                          | Measure SQL/network/pool behavior under matched topology; do not infer performance from language alone          |
| Idle allocator pages stayed resident after bursts                               | Measure post-load recovery and configure purging only with evidence                                             |
| A source move broke the old Vercel build, shortening rollback options           | Preserve immutable TS image plus tested build configuration before moving/deleting source                       |
| DNS moved before the new TLS certificate was ready                              | Verify external certificate/routing before traffic switch; reuse the existing hostname/service when possible    |

Rocal's `xtask/src/check.rs` now runs formatting, clippy, workspace tests, the full API suite in both modes, OpenAPI and entity checks, completed test destinations and memory checks. Astral Grove should have one equally explicit final gate, with its extra shared Zod, Expo, image, sync and migration checks.

## Files deliberately excluded from reuse

Do not copy Rocal's production secrets, environment files, private data, service IDs, backup dumps, passkey credentials, Railway test-host allowances, Go/Rust notification infrastructure or private mail integrations. Do not copy old rollout commands that delete a test environment or move a production domain. The reference is an implementation and validation pattern; Astral Grove gets its own target guards, fixtures, runbook and rollback proof.

## Applied to Astral Grove

The implemented counterparts are `apps/backend`, `crates/astral-grove-api-types`, `packages/api-contracts`, and `cargo xtask openapi|baseline`. The original server is frozen in `tests/reference-api`, excluded from the native image, and used for executable comparisons. Drizzle-compatible migration history is owned by Rust rather than a production Bun subprocess.

The implementation retained Zod unknown-key stripping/default/coercion semantics, the seven-day Better Auth protocol and existing database precision. It added current-source differential suites alongside generated types, as motivated by the Rocal audit. All 135 shared output schemas have bidirectional type assertions; the native inventory gate checks 55 application operations and 42 auth method/path pairs. The detailed function, case, migration and local container results are in [local-validation.md](local-validation.md).

Differences from the proposed Rocal layout are deliberate: explicit parameterized SQL preserves the existing PostgreSQL behavior without a parallel generated entity schema; the original TypeScript unit cases remain an oracle instead of being represented as 398 newly written Rust tests; local fixtures replace Rocal's hosted test infrastructure for this task. No Rocal production settings, mail accounts, worker code, secrets or resources were copied.
